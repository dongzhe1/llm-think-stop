# llm-think-stop

Code that measures how many reasoning tokens an early-exit rule saves when it must keep a certified bound on lost
correct answers. Reasoning traces are sampled from open reasoning models on six benchmarks. Each trace is probed for an
answer at fixed token budgets: the probe closes the reasoning and asks for the final answer. The pipeline then compares
three kinds of policy on the logged probes: a learned stopping rule (LearnStop, a logistic model on probe confidence,
answer stability, budget and backtracking markers), a static token budget, and single-signal confidence rules. Every
policy is certified with Learn-then-Test (exact binomial p-values, fixed-sequence testing) before it is evaluated. The
repository reproduces the result files in `results/` from the logged probe records.

## Demo

> **Note on data:** the logged probe records are not stored in this repository (binary NumPy archives of model
> outputs, about 60 MB, regenerated by `bash run.sh full`). The demo uses **synthetically generated fake data**
> (`scripts/make_fake_probes.py`) solely to verify that the analyses run end to end. The results **cannot be used to
> evaluate the actual findings**.

```bash
bash run.sh fake
```

This writes 18 synthetic probe records under `fake/probes/` (five task/model settings with evaluation and training
splits for trace seed 0, plus two settings for seeds 1 and 2), runs the eight analyses on them, and copies the result
files to `fake/results/`, laid out like `results/`. `SPLITS=5 bash run.sh fake` uses 5 instead of 50 calibration/test
splits and runs faster.

Expected output (excerpt):

```
--- <repo>/scripts/make_fake_probes.py <repo>/fake/probes
wrote 18 synthetic probe records -> <repo>/fake/probes
--- <repo>/scripts/analyze_v2.py --root <repo>/fake/probes/seed0 --out <repo>/fake/analyses/analysis --splits 50
...
--- <repo>/scripts/analyze_v2_extra.py --root <repo>/fake/probes/seed0 --out <repo>/fake/analyses/fine --fine_static --splits 50
...
results -> <repo>/fake/results
```

**Expected run time:** several minutes on a normal desktop computer; on the machine above, the first four of the eight
analyses took about 75 seconds together.

## Data Requirements

### 1. Question files: `data/<task>_<split>.jsonl`

Written by `scripts/prepare_reason_v2.py`; `<split>` is `eval` (calibration and test) or `train` (training pool of the
learned rule, disjoint from the evaluation set).

```
id, task, mode, n_options, question, gold, category
```

**Key Fields**:
* **mode**: how the answer is graded: `numeric` (number equality), `math` (LaTeX normalisation with a numeric
  fallback), `mc` (option letter), `text` (normalised exact match).
* **n_options**: number of answer options for `mc` questions, 0 otherwise.
* **gold**: reference answer as a string.
* **category**: MMLU-Pro subject or BBH subtask; empty for the other tasks.

### 2. Probe records: `probes/seed<k>/<task>_<split>__<model>/`

Written by `scripts/reason_learnstop_v2.py` (GPU). `raw.npz` holds one row per question:

```
budgets, think_len, closed, prompt_len, gen_len, active, txt_line, txt_full, len_line, len_full, lp, ent, mkr,
resp_text, gold, mode, n_options, category, qid
```

**Key Fields**:
* **budgets**: the 14 checkpoints in reasoning tokens (0 to 12,288).
* **think_len**, **closed**: reasoning tokens of the trace and whether the model closed its reasoning before the cap.
* **active** (question × checkpoint): the checkpoint falls inside the trace, so a probe was decoded there.
* **txt_line**, **txt_full** (question × checkpoint + end of trace): the probe continuation up to the first newline,
  and up to 48 tokens. The last column is the probe after the complete trace.
* **len_line**, **len_full**: decoded probe lengths in tokens.
* **lp**, **ent** (question × probe × 48): per-token log-probability and top-20 entropy of the probe continuation.
* **mkr**: backtracking-marker density of the reasoning prefix (markers per 100 tokens).
* **resp_text**, **gen_len**: the model's own response after the reasoning and the total tokens generated.

`meta.json` records the data file, model tag, sampling settings, token budget and probe suffix of the run.
`fine_probes.npz` (written by `scripts/probe_fine_grid.py` for the evaluation splits) repeats the probe on the logged
traces every 128 tokens up to 1,024 and every 256 tokens after that, with the same `txt_*`, `len_*`, `active`,
`budgets` and `qid` fields and no log-probabilities.

### 3. Model weights: `$MODELS_DIR/<model>/`

One directory per model, named as in the table below.

## Data Preprocessing

`scripts/prepare_reason_v2.py` builds an evaluation set and a disjoint training pool per task (seed 42) and asserts
that no training question appears in the evaluation set:

| Task | Evaluation set | Training pool |
|---|---|---|
| GSM8K | test split, 1,319 | 500 from the train split |
| MATH-500 | MATH-500, 500 | 500 from the MATH train split |
| MMLU-Pro | 1,000 from the test split | 500 other test questions |
| GPQA | Diamond, 198 | Extended minus Diamond, 348 |
| AQuA-RAT | test + validation, 508 | 500 from the train split |
| BBH (dyck_languages, word_sorting) | 150 per subtask, 300 | 100 per subtask, 200 |

The question files were pulled from the Hugging Face Hub on 2026-09-24 (GPQA on 2026-09-26). The hosted datasets can
change, so a new pull may give slightly different question files.

`scripts/reason_learnstop_v2.py` samples one reasoning trace per question with the model family's recommended decoding
(temperature 0.6, top-p 0.95; top-k 20 for Qwen3) up to a reasoning cap of 8,192 tokens (GSM8K, AQuA, BBH), 12,288
(MMLU-Pro) or 16,384 (MATH-500, GPQA). It cuts the token sequence of the trace at each checkpoint, appends
`</think>` and `Final answer:`, and decodes greedily for at most 48 tokens. The same probe after the complete trace
gives the full-thinking answer. All settings use trace seed 0; GSM8K / Qwen3-32B and MMLU-Pro / Qwen3-8B are repeated
with seeds 1 and 2. The analyses grade every probe offline (`scripts/grading_v2.py`), split each evaluation set 50
times into calibration and test halves, certify policies on the calibration half and report costs and risks on the test
half.

## Usage

### 1. Obtain the inputs

Download the model weights into one directory, one subdirectory per model:

```bash
export MODELS_DIR=/path/to/models
for m in Qwen/Qwen3-8B Qwen/Qwen3-32B deepseek-ai/DeepSeek-R1-Distill-Qwen-7B \
         deepseek-ai/DeepSeek-R1-Distill-Llama-8B THU-KEG/AdaptThink-7B-delta0.05; do
    hf download "$m" --local-dir "$MODELS_DIR/${m#*/}"
done
```

GPQA is gated: accept its terms on the Hugging Face Hub and run `hf auth login` once, which stores the token under
`~/.cache/huggingface/`. The other datasets download without a token.

### 2. Run

```bash
MODELS_DIR=/path/to/models OUT_DIR=/path/to/run bash run.sh full
```

This prepares the question files (`$OUT_DIR/data/`), generates the probe records (`$OUT_DIR/probes/seed0`, `seed1`,
`seed2`), repeats the probes on the fine grid, runs the eight analyses (`$OUT_DIR/analyses/`) and collects the result
files in `$OUT_DIR/bundle/`, laid out like `results/`. `DRY=1` prints the commands without running them. `TP32=1` runs
Qwen3-32B on one GPU instead of two. Every generation step resumes where it stopped when the command is repeated.

To recompute only the analyses from existing probe records (CPU):

```bash
PROBES_DIR=/path/to/probes OUT_DIR=/path/to/run DATA_DIR=/path/to/run/data bash run.sh analyze
```

`PROBES_DIR` holds `seed0/` and, if available, `seed1/` and `seed2/`. `DATA_DIR` is needed only to grade the BBH
Dyck-language answers, whose references are read from the question files.

### 3. Check the results

`results/MANIFEST.txt` lists every result file with its row count and the first 16 hex digits of its SHA-256. Compare
the files in `$OUT_DIR/bundle/` with those in `results/`; the `.csv.gz` files differ only in their gzip headers, so
compare them after decompression.
